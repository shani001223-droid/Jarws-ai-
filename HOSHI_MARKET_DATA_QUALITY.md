# HOSHI Task 37 — Independent Public Spot Candle and Volume Quality

Development-only, no live orders, account connection, leverage, signals or paid APIs.

`GET /api/trading/data-quality?symbol=BTCUSDT&interval=15m` supports only BTCUSDT and ETHUSDT on 15m, 1h or 4h. It retrieves **fixed** public Binance Spot USDT and Kraken Spot USD OHLC feeds in parallel. No user-controlled host, credential, trading endpoint or arbitrary pair is accepted. The two venue prices are independent; BTC/USD and BTC/USDT are not identical markets. A 2% tolerance over the last three matching closed candle closes is an operational disagreement threshold, not a guarantee of truth.

Binance data must contain 12-field OHLCV rows, continuous aligned timestamps, positive recent base volume, plausible quote USDT volume (bounded by the candle's high/low multiplied by base volume), valid trade count and taker-buy volumes. Kraken OHLC data must have a clean error list, one pair, aligned continuous timestamps, valid OHLC/VWAP/base volume/trade count. Both must have at least 64 fresh *closed* candles. A forming last bar is excluded. Both fetched timestamps must be current and within 120 seconds. Any outage, stale source, gap, malformed volume or price/time disagreement returns a sanitized 503 rather than a verified claim. All results explicitly label the venues and the units; volume figures across venues must **not** be compared numerically.

The endpoint uses the existing bounded public-data cache (30 seconds), two shared research request slots and existing seven-second upstream timeout. Its successful response is no-store, includes closed-candle timestamp, source retrieval timestamps, separate Binance base/quote and Kraken base volumes, price difference, and `orders_enabled=false`. It is a read-only data-quality inspection, **not** a new trading recommendation. The pre-existing `/api/trading/research` and historical backtest are still Binance-only and are **not** certified by this independent check; future multi-timeframe setup work must not silently claim otherwise.

Offline regression fixtures in `tests/test_market_data_quality.py` exercise valid multi-interval data, closed-bar exclusion, fixed hosts, malformed/stale/gapped feeds, inconsistent quote/taker volumes, independent price mismatch, API no-store and slot release. A passing fixture test is not proof that both public feeds are reachable from Render, that Kraken will always publish continuous bars, or that a Realme Note 50 received current quotes. A successful live dual-source smoke on the **same deployment/environment** is still required before claiming live provider acceptance. No production deploy or physical phone test was performed as part of the source change.
